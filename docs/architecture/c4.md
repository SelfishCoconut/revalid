# Architecture — C4 model

> Authored diagrams: these do NOT auto-sync with code. Any PR changing a flow or boundary
> depicted here must update this page (checked by the `doc-curator` agent).

## Level 1 — System context

```mermaid
C4Context
    title System context — revalid
    Person(auditor, "Security auditor / developer", "Wants to know if reported findings are fixed")
    System(revalid, "revalid", "Parses pentest reports and re-validates findings against authorized targets")
    System_Ext(llm, "LLM backend", "Claude API or local Ollama, selected by config (ADR-0010); interprets findings and reproduction steps")
    System_Ext(lab, "Authorized lab targets", "Systems under retest (Juice Shop, DVWA, ...)")
    Rel(auditor, revalid, "Provides report, receives revalidation verdicts")
    Rel(revalid, llm, "Sends finding text (synthetic/lab data only)")
    Rel(revalid, lab, "Executes non-destructive verification probes")
```

## Level 2 — Containers

The whole tool runs from one `uvicorn` process bound to `127.0.0.1` (NFR-03):
FastAPI serves the React SPA at `/` and the JSON API under `/api` (ADR-0013).

```mermaid
C4Container
    title Containers — revalid (M3)
    Person(auditor, "Security auditor / developer")
    System_Boundary(revalid, "revalid (localhost only — NFR-03)") {
        Container(spa, "React SPA", "Vite/React/TS/Tailwind (FR-11)", "Report overview, plan review/edit/approve, verdict + evidence drill-down")
        Container(api, "FastAPI app", "Python, /api", "Ingest, extraction, plan/approve gate, retest executor; serves the SPA at /")
        Container(worker, "Ingest worker", "Background task", "Runs FR-01 PDF parse -> FR-03 LLM extraction off the request path")
        ContainerDb(db, "SQLite", "SQLAlchemy", "Reports, findings, plan versions, verdicts + evidence")
    }
    System_Ext(llm, "LLM backend", "Claude / Ollama (ADR-0010)")
    System_Ext(lab, "Authorized lab targets", "Juice Shop, ... (FR-06 allowlist)")
    Rel(auditor, spa, "Uploads report, approves plans, reads verdicts", "localhost")
    Rel(spa, api, "JSON over /api", "fetch")
    Rel(api, worker, "schedules extraction")
    Rel(worker, llm, "extracts findings (synthetic/lab data only)")
    Rel(api, db, "reads / writes")
    Rel(worker, db, "persists findings")
    Rel(api, lab, "non-destructive probes via the FR-06 allowlist guard")
```

## Level 3 — Walking-skeleton retest flow (M1)

The deterministic slice shipped in M1 (FR-02 → FR-07 → FR-09): a finding is
retested by one verification-only probe, executed **only** through the FR-06
allowlist guard, producing an evidence-backed verdict.

```mermaid
sequenceDiagram
    actor Dev as Auditor/Dev
    participant API as FastAPI (app.py)
    participant DB as SQLite
    participant RT as Retest engine (retest.py)
    participant G as AllowlistTransport (FR-06)
    participant Lab as Juice Shop (lab)

    Dev->>API: POST /api/findings/import (DefectDojo JSON)
    API->>DB: persist Finding
    Dev->>API: POST /api/findings/{id}/retest
    API->>RT: run_probe(login_sqli_probe)
    RT->>G: POST /rest/user/login  (' OR 1=1--)
    G->>G: guard.check(url) — deny if not allowlisted
    G->>Lab: forward (only if allowed)
    Lab-->>RT: 200 + auth token  (evidence)
    RT->>RT: assess → still_open / fixed / inconclusive
    RT-->>API: Verdict (+ linked Evidence)
    API->>DB: persist Verdict
    API-->>Dev: Verdict JSON
```

## Level 3 — FR-11 UI ingest → verdict flow (M3)

The full flow operated from the React SPA alone (FR-11 acceptance): a PDF report
is uploaded, extracted into findings by a background worker the UI polls, then a
plan is generated, approved (FR-05 gate), and executed, yielding verdicts with
evidence — every step a UI action over `/api` (ADR-0013).

```mermaid
sequenceDiagram
    actor U as Auditor (browser)
    participant SPA as React SPA
    participant API as FastAPI (/api)
    participant W as Ingest worker (background)
    participant DB as SQLite
    participant LLM as LLM backend
    participant RT as Retest executor (FR-06 guard)
    participant Lab as Lab target

    U->>SPA: drop PDF report
    SPA->>API: POST /api/reports (multipart)
    API->>DB: insert report (extracting)
    API-->>SPA: 202 report
    API->>W: schedule extraction
    W->>LLM: FR-01 parse → FR-03 extract
    W->>DB: insert findings (report_id); report → ready
    loop poll until ready / failed
        SPA->>API: GET /api/reports/{id}
        API-->>SPA: {status, ...}
    end
    U->>SPA: review finding → Generate plan
    SPA->>API: POST /api/findings/{id}/plan
    U->>SPA: Approve
    SPA->>API: POST /api/findings/{id}/plan/approve
    U->>SPA: Run retest
    SPA->>API: POST /api/findings/{id}/retest
    API->>RT: execute_approved_plan (FR-05 chokepoint)
    RT->>Lab: non-destructive probe (allowlisted)
    Lab-->>RT: response (evidence)
    RT->>DB: persist verdicts (plan_version)
    API-->>SPA: [verdicts + evidence]
    SPA-->>U: verdicts, evidence drill-down, plan history
```
