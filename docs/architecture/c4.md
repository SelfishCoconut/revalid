C4Context

    Person(auditor, "Security auditor / developer", "Wants to know if reported findings are fixed")

## Level 2 — Containers

The whole tool runs from one `uvicorn` process bound to `127.0.0.1` (NFR-03):
FastAPI serves the React SPA at `/` and the JSON API under `/api` (ADR-0013).

```mermaid
C4Container
    title Containers — revalid (M4)
    Person(auditor, "Security auditor / developer")
    System_Boundary(revalid, "revalid (localhost only — NFR-03)") {
        Container(spa, "React SPA", "Vite/React/TS/Tailwind (FR-11)", "Report overview, plan review/edit/approve, verdict + evidence drill-down")
        Container(api, "FastAPI app", "Python, /api", "Ingest, extraction, plan/approve gate, sanity-guarded retest executor (FR-08), audit re-derivation (FR-10), versioned export (FR-12); serves the SPA at /")
        Container(worker, "LLM worker", "Background task", "Runs FR-01 PDF parse -> FR-03 extraction and FR-04 plan generation off the request path (ADR-0022)")
        ContainerDb(db, "SQLite", "SQLAlchemy", "Reports, findings, plan versions, verdicts + evidence + audit stamps (created_at / actor)")
    }
    System_Ext(llm, "LLM backend", "Claude / Ollama (ADR-0010)")
    System_Ext(lab, "Authorized lab targets", "Juice Shop, ... (FR-06 allowlist)")
    Rel(auditor, spa, "Uploads report, approves plans, reads verdicts", "localhost")
    Rel(spa, api, "JSON over /api", "fetch")
    Rel(api, worker, "schedules extraction / plan generation")
    Rel(worker, llm, "extracts findings, proposes plans (synthetic/lab data only)")
    Rel(api, db, "reads / writes")
    Rel(worker, db, "persists findings")
    Rel(api, lab, "non-destructive probes via the FR-06 allowlist guard")
```

## Level 3 — Walking-skeleton retest flow (M1)

The deterministic slice shipped in M1 (FR-02 → FR-07 → FR-09): a finding is
retested by one verification-only probe, executed **only** through the FR-06
allowlist guard, producing an evidence-backed verdict.

```mermaid
sequenceDiagram
    actor Dev as Auditor/Dev
    participant API as FastAPI (app.py)
    participant DB as SQLite
    participant RT as Retest engine (retest.py)
    participant G as AllowlistTransport (FR-06)
    participant Lab as Juice Shop (lab)

    Dev->>API: POST /api/findings/import (DefectDojo JSON)
    API->>DB: persist Finding
    Dev->>API: POST /api/findings/{id}/retest
    API->>RT: run_probe(login_sqli_probe)
    RT->>G: POST /rest/user/login  (' OR 1=1--)
    G->>G: guard.check(url) — deny if not allowlisted
    G->>Lab: forward (only if allowed)
    Lab-->>RT: 200 + auth token  (evidence)
    RT->>RT: assess → still_open / fixed / inconclusive
    RT-->>API: Verdict (+ linked Evidence)
    API->>DB: persist Verdict
    API-->>Dev: Verdict JSON
```

## Level 3 — FR-11 UI ingest → verdict flow (M3)

The full flow operated from the React SPA alone (FR-11 acceptance): a PDF report
is uploaded, extracted into findings by a background worker the UI polls, then a
plan is generated the same way — a `202` reserves a `generating` version the
worker settles to `proposed`/`failed` while the SPA polls `/plans` (ADR-0022) —
approved (FR-05 gate), and executed, yielding verdicts with
evidence — every step a UI action over `/api` (ADR-0013). The `execute_approved_plan`
edge is shown here as one step; M4 (FR-08, below) interposes the sanity checker
inside it — see [FR-08 guarded execution](#level-3-fr-08-guarded-execution-m4).

```mermaid
sequenceDiagram
    actor U as Auditor (browser)
    participant SPA as React SPA
    participant API as FastAPI (/api)
    participant W as Ingest worker (background)
    participant DB as SQLite
    participant LLM as LLM backend
    participant RT as Retest executor (FR-06 guard)
    participant Lab as Lab target

    U->>SPA: drop PDF report
    SPA->>API: POST /api/reports (multipart)
    API->>DB: insert report (extracting)
    API-->>SPA: 202 report
    API->>W: schedule extraction
    W->>LLM: FR-01 parse → FR-03 extract
    W->>DB: insert findings (report_id); report → ready
    loop poll until ready / failed
        SPA->>API: GET /api/reports/{id}
        API-->>SPA: {status, ...}
    end
    U->>SPA: review finding → Generate plan
    SPA->>API: POST /api/findings/{id}/plan
    API->>DB: insert plan version (generating)
    API-->>SPA: 202 plan
    API->>W: schedule generation
    W->>LLM: FR-04 propose → FR-06 gate
    W->>DB: settle version → proposed / failed (ADR-0022)
    loop poll until proposed / failed
        SPA->>API: GET /api/findings/{id}/plans
        API-->>SPA: [plan versions]
    end
    U->>SPA: Approve
    SPA->>API: POST /api/findings/{id}/plan/approve
    U->>SPA: Run retest
    SPA->>API: POST /api/findings/{id}/retest
    API->>RT: execute_approved_plan (FR-05 chokepoint)
    RT->>Lab: non-destructive probe (allowlisted)
    Lab-->>RT: response (evidence)
    RT->>DB: persist verdicts (plan_version)
    API-->>SPA: [verdicts + evidence]
    SPA-->>U: verdicts, evidence drill-down, plan history
```

## Level 3 — FR-08 guarded execution (M4)

M4 makes the retest chokepoint self-checking (ADR-0014). `execute_approved_plan`
runs each approved probe through `guarded_run` (`sanity.py`), an **independent
verifier** wrapped around the probe: it re-checks the probe is a member of the
approved plan **before** any socket opens (fail-closed — a deviation raises and
never executes), and **downgrades** an over-confident verdict **after**
(a `fixed` on a 404/410 or 3xx becomes `inconclusive`, since a moved endpoint is
not a proven fix). It only ever removes confidence, never manufactures it.

```mermaid
sequenceDiagram
    participant API as FastAPI (/api)
    participant EX as execute_approved_plan (approval.py)
    participant DB as SQLite
    participant GR as guarded_run (sanity.py, FR-08)
    participant RT as run_probe (retest.py)
    participant Lab as Lab target (FR-06 guard)

    API->>EX: POST /api/findings/{id}/retest (approved plan)
    EX->>DB: load approved plan version → probes
    loop each approved probe
        EX->>GR: guarded_run(client, probe, approved)
        GR->>GR: assert_in_plan(probe, approved)
        alt probe not in approved plan
            GR-->>EX: raise PlanDeviationError
            EX-->>API: 409 (execution blocked — no verdict stored)
        else probe is approved
            GR->>RT: run_probe(client, probe)
            RT->>Lab: non-destructive probe (allowlisted)
            Lab-->>RT: response (evidence)
            RT-->>GR: Verdict (+ evidence)
            GR->>GR: review_verdict — downgrade ambiguous "fixed" → inconclusive
            GR-->>EX: verdict (possibly downgraded)
            EX->>DB: persist verdict (created_at, actor=executor)
        end
    end
    EX-->>API: [verdicts]
```

## Level 3 — FR-10 audit re-derivation & FR-12 export (M4)

Two read-only derivations off the persisted trail, no network. **FR-10**
(ADR-0015): a verdict is a pure function of its stored evidence, so `rederive_run`
recomputes every verdict from the same `assess_evidence` + `review_verdict` the
live path uses and diffs it against storage — reproduced from the trail alone.
**FR-12** (ADR-0016): `build_export` assembles the whole run into one
`SCHEMA_VERSION`-versioned document that validates against a schema *generated*
from the model, so the published schema can never drift from the document.

```mermaid
sequenceDiagram
    actor U as Auditor / FR-15 harness
    participant API as FastAPI (/api)
    participant AU as audit.py (FR-10)
    participant EXP as export.py (FR-12)
    participant DB as SQLite

    U->>API: GET /api/audit
    API->>AU: rederive_run(session)
    AU->>DB: read every verdict + its evidence
    AU->>AU: rederive_verdict = review_verdict(assess_evidence(evidence))
    AU->>AU: diff re-derived vs stored → discrepancies
    API-->>U: AuditReport {total, reproduced, discrepancies}

    U->>API: GET /api/export
    API->>EXP: build_export(session)
    EXP->>DB: read reports, findings, plans, verdicts (id order)
    EXP-->>API: RunExport {schema_version, generator, metrics, ...}
    U->>API: GET /api/export/schema
    API->>EXP: export_schema() = RunExport.model_json_schema()
    API-->>U: JSON Schema (matches docs/reference/schemas/run-export.schema.json)
```
